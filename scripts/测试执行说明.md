# 毕业设计中期检查视频录制说明

本文档用于中期检查视频录制。录制目标不是展示所有代码细节，而是证明当前系统已经具备 ROS2 多节点运动控制系统的核心能力：

- 能启动 UR5 Gazebo 仿真和本项目系统节点。
- 能通过 `/move_joints` Action 接收运动任务。
- 能完成“任务入口 -> 轨迹规划 -> 控制执行 -> Gazebo 接口适配 -> 关节状态反馈”的完整链路。
- 能通过 `/motion_event`、`/task_state`、`/system_state` 观察任务生命周期。
- 能记录 rosbag，支持后续实验复现。
- 能处理非法输入，并支持 reset 复位。

建议视频时长控制在 8 到 10 分钟。录制时优先让老师看到“机械臂运动 + 状态变化 + Action 反馈”，不要把时间花在长时间编译或逐行解释代码上。

## 2. 视频开场讲解

建议先展示 `README.md` 或 `docs/architecture/system_architecture.md`。

讲解词参考：

```text
本项目是基于 ROS2 的工业机器人运动控制系统架构设计与仿真验证，研究对象为 UR5 工业机器人，运行环境为 Ubuntu 22.04、ROS2 Humble 和 Gazebo。

当前中期阶段已经完成系统核心链路，包括任务入口层、轨迹规划层、控制执行层、机器人接口层和系统管理层。接下来演示从 /move_joints Action 发送运动任务，到 Gazebo 中 UR5 执行运动，并通过状态 topic 反馈任务生命周期的完整过程。
```

可以展示或口播核心链路：

```text
/move_joints
  -> /motion_command
  -> /planned_traj
  -> /joint_cmd
  -> /joint_trajectory_controller/joint_trajectory
  -> /joint_states
```

再说明状态链路：

```text
业务节点
  -> /motion_event
system_manager_node
  -> /task_state
  -> /system_state
```

讲解重点：

- `/move_joints` 是外部任务入口。
- `/planned_traj` 是规划结果。
- `/joint_cmd` 是控制层输出。
- `/joint_states` 是仿真机器人反馈。
- `/task_state` 是正式任务状态。
- `/system_state` 是系统级状态。

## 15. 常见问题处理

### 15.1 `ros2 control list_controllers` 执行失败

现象：

```text
ros2: error: invalid choice: 'control'
```

原因：

```text
当前环境没有安装 ros2controlcli 命令扩展。
```

处理：

```bash
ros2 topic echo /joint_states --once
ros2 topic list | grep joint_trajectory
ros2 node list
```

视频中说明：

```text
当前环境未安装 ros2 control 命令扩展，因此使用 /joint_states、joint_trajectory 话题、Gazebo 运动和任务状态变化作为运行依据。
```

### 15.2 机械臂运动不明显

当前测试脚本已经把 `test-fast`、`test-normal`、`test-alt`、`test-slow` 调整为更大幅度、更明显速度差异的目标。录制时建议：

- 先执行 `test-fast` 或 `test-normal`。
- 完成后立即执行 `test-alt`。
- 再执行 `test-slow` 做速度对比。
- Gazebo 视角拉近 UR5 机械臂。
- 同时展示 `/joint_states` 或 `/task_state`，用数据证明运动过程。

观察关节位置变化：

```bash
ros2 topic echo /joint_states --field position
```

### 15.3 rosbag 怎么停止和查看

停止：

```text
在录制终端按 Ctrl+C
```

查看：

```bash
ros2 bag info $(ls -td bags/graduation_test_* | head -1)
```

回放：

```bash
ros2 bag play $(ls -td bags/graduation_test_* | head -1)
```

### 15.4 任务失败后怎么办

先执行 reset：

```bash
./scripts/run_graduation_tests.sh reset
```

然后重新观察系统状态：

```bash
ros2 topic echo /system_state --once
```

确认系统恢复后，再重新发送测试任务。
